# 首批 Next.js 静态页面方案

状态：用户于 2026-09-20 回复“同意”，方案已批准；三个页面已本地实现，尚未独立验收、集成或发布。

## 目标与范围

按用户已决定的方向：D23 决定内容、文案和页面设计，D32 负责开发、验证与发布；网站无需运营后台，采用 Next.js 静态页面，不再把 WordPress 作为新页面的运行依赖。

本批仅实现三个英文页面：

| 页面 | 路径 | 本批结果 |
|---|---|---|
| 首页 | `/` | 沿用批准的首页内容、布局与共享导航 |
| 产品集合页 | `/products/` | 保留批准的产品分类、筛选与产品目录；M350 可进入详情 |
| M350 产品详情页 | `/products/m-350/` | 沿用批准的 M350 内容、技术数据和详情布局 |

不新增其他产品详情页、询价页、后台、数据库、内容 API 或通用页面管理器。不删除旧 WordPress 实现，不切换生产环境。

## 实现结构

在 D32 仓库的 `static-site/` 中建立独立 Next.js 应用，使用静态导出。此目录是本批迁移的隔离边界，并非长期维护两套网站的决定。

- `app/`：三个页面路由、布局和页面元数据。
- `components/`：唯一的 Header、Footer、菜单、Cookie Settings，以及各页面组件。
- `content/`：随代码版本管理的内容文件。页面模板读取这些文件，不读取 WordPress。
- `public/`：本站使用的图片、字体等本地静态资源。
- `tests/`：静态输出、页面交互及响应式检查。

复用 D16 已有 Next.js 组件、样式和资源，但只移植本批必要的依赖。去掉 WordPress 查询、多站点运行配置及依赖服务端的询价归因接口。不为三个页面再建一套内容平台。

新增页面的常规方式是：D23 给出批准内容与设计 → D32 添加内容文件、复用或增加页面组件及路由 → 测试 → 按发布流程交付。

## 内容和链接规则

当前内容基线由以下 D23 入口确定，实施时沿其引用核对批准输入：

- HOME-001：`HOME-001_CURRENT_GATE_BASELINE_MANIFEST_V1.12.md`。
- PRODUCT-000：`PRODUCT-000_D32_CURRENT_GATE_BASELINE_MANIFEST_V0.2.md`。
- GRADE-M350：`GRADE-M350_D32_CURRENT_GATE_BASELINE_MANIFEST_V0.7.md`。

D16 仅提供可复用实现，不自动成为新版文案依据。当前 D32 canonical 域名为 `https://tio2products.com`，不因复用 D16 代码而改成参考站域名。

产品集合页保留批准的产品身份与顺序，但本批只有 M350 获得可用详情链接。其他未实现目标继续遵循批准的未就绪展示规则，不创建假页面、假成功响应或暗中跳转到旧站。条件模块按实际依赖可用性展示。

询价表单确定采用 Web3Forms，浏览器直接提交，无自建接收后端；本批不新增询价页，也不宣称询价链路已打通。技术参数不推测、不填补未批准值。审批编号和本机路径仅作开发追溯，不进入访客页面。

## 构建与兼容

配置静态导出与尾斜杠路径。页面所需内容在构建期可用，构建和部署制品不依赖 D16、D23 本机目录或 WordPress 服务。使用适合静态托管的图片方式，不要求 Next.js 图片服务。

旧 WordPress 运行环境、数据库、媒体卷和已有发布工作流保持不动。本批先交付本地静态预览与静态文件；生产托管切换、旧系统下线另行明确。不启用索引，沿用当前 noindex 边界。

## 验收标准

1. 独立安装依赖、类型检查和静态构建成功，生成三个路径的 HTML。
2. 关闭或不连接 WordPress 时，三页内容及范围内交互仍正常。
3. 首页、集合页和 M350 之间导航正常；其他依赖真实记录，不伪装完成。
4. 文案、技术数据、标题、canonical 和结构化数据核对批准输入；不泄露跨站内容或内部审批信息。
5. 产品筛选、菜单、Cookie Settings 及适用 FAQ 交互可用，键盘焦点正常；桌面、平板和手机宽度无页面级横向溢出。
6. 浏览器无相关控制台错误，无 WordPress 或自建 API 请求，静态资源正常加载。
7. 保存新的测试结果与截图，不覆盖旧验收证据。旧 WordPress Gate9 结论不自动转移到新版；新页面独立验收另行进行。
