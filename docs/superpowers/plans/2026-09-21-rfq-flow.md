# RFQ Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Migrate the approved public RFQ page, its guarded Thank You destination, and the English Privacy Policy into the standalone Next.js static site without changing the original content or behavior.

**Architecture:** Store approved visitor content in versioned JSON, render three static App Router routes through the existing Malaysia shared chrome, and isolate browser-only RFQ behavior in focused client modules. Submit directly to Web3Forms, create a short-lived session receipt only after provider acceptance, and treat missing receiver configuration or uncertain responses as failure rather than success.

**Tech Stack:** Next.js 16 static export, React 19, TypeScript 5.9, CSS Modules, Playwright, Node test runner, Web3Forms browser API.

**Spec:** docs/superpowers/specs/2026-09-21-rfq-page-reference-design.md

## Global Constraints

- The current public pages at https://tio2malaysia.com/request-a-quote/, /thank-you/, and /privacy-policy/, captured on 2026-09-21, are the content and behavior baseline. Do not invent or rewrite fields, copy, options, errors, or legal text.
- Implement only /request-a-quote/, /thank-you/, and /privacy-policy/. Sample, Documents, BM Privacy, and Cookie Policy remain explicit unresolved routes.
- Preserve canonical origin https://tio2products.com, trailing slashes, static export, and global noindex/nofollow.
- Reuse the existing Header, Footer, Menu, Cookie Settings, tokens, and breakpoints.
- Web3Forms is the only receiver. Do not add an API route, database, server action, file upload, analytics activation, CAPTCHA, or marketing-consent field.
- Browser tests must intercept https://api.web3forms.com/submit and must never send a real submission.
- Do not commit or print the production routing key. Production reads NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY from Vercel; tests build with 00000000-0000-4000-8000-000000000001.
- Keep current RFQ links clean. Only explicit approved query parameters may prefill the form.

## Review Focus

- Forged Thank You URLs without a fresh matching receipt must show direct mode, never success. Task 2 tests this.
- Network error, timeout, 429, malformed response, and provider rejection must retain values and create no receipt. Task 4 tests this.
- Unknown/conflicting prefill parameters and the M-2377/Specialty Materials exclusion must remain fail-closed. Task 5 tests this.
- Missing/malformed receiver configuration must show unavailable and fail production smoke. Tasks 3 and 6 test this.
- Privacy text must preserve ten sections, Web3Forms processing, retention, and contact facts. Task 1 tests this.
